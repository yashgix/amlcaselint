Problem

Which cited failures can a rule check?

Enforcement orders say what examiners found wrong: SARs filed late, alerts left unreviewed, cases closed with no reason. Some of those failures can be written as a rule over an alert log. Some cannot. This project separates the two and keeps every claim tied to the order text.

No real alert data is public, so the checks run on a clearly synthetic log. Its rates describe the checks, never a bank.

How it works

Three parts, one data flow

  1. The corpus is the 50 actions FinCEN tags Depository Institutions. 39 have a text layer and are used. Text is pinned with sha256 hashes.
  2. A frozen keyword baseline flags sentences in ten failure categories. The patterns were fixed before any labelling.
  3. Fifteen orders are labelled from the pinned text by one labeller, Claude (Opus 5.5), an Anthropic model, each label with an exact quote. The baseline is scored against them.
  4. Four checks run on the alert log: late SAR, aged alert, closure without rationale, closure only because a filing existed.

Limits

What this does not show

  • The alert log is synthetic. No claim is made about any bank.
  • One labeller (Claude, Opus 5.5) and 15 orders. No person has spot-checked the labels yet, so scores are rough.
  • Document-level scores are generous. Evidence recall is 0.542.
  • The categories are a judgement call. Legal boilerplate is also matched, and OCR errors in older orders can affect matching.
  • Eight scanned orders and three actions against individuals are excluded. Other regulators' orders are out of scope.

Technical details

Method, results and data terms

Labelling and scoring

Labels count only what FinCEN states in its own findings section of each order (its Determinations, or the Statement of Facts in newer orders). A sentence there may cite another regulator's examination. A separate section that summarises another regulator's own enforcement action is not counted. The baseline patterns were frozen before labelling, so the gold set could not be tuned to them.

Document-level scoring counts an order as a hit for a category when any flagged sentence in it has that category. Evidence recall counts a gold quote as covered only when a flagged sentence of the same category overlaps it.

The generator seeds exactly the cases the rules flag, so these columns show that the code matches its specification. They do not show that it finds real defects. The naive rules are written to be wrong. Their columns show what each rule detail is for, such as separating the 30-day legal deadline from a bank's own 30-day review limit.

Findings say how sure they are

  • Findings with status. review returns one finding per flagged alert. On the synthetic log: 19,300 defects, 1,000 risks, 0 cannot_assess. Each carries the order quote, and late_sar findings also carry the regulation quote. Undecided alerts past the SAR deadline and closures citing only a prior filing are risks, not defects.
  • Cannot assess. A missing input is not read as clean. --cannot-assess lists alerts a check cannot decide.
  • Legal deadline versus policy. The SAR deadline and the alert review limit are separate constants.
  • Baseline failure analysis. Every miss and false hit is listed with its sentence.

One rejected label

A proposed extra label (Lone Star, 18845, independent testing) was rejected because its sentence is in a section that summarises the OCC's own earlier action, not in FinCEN's own findings. So v1 stands at micro F1 0.836. The rejected label would have given 0.843.

make test
make experiment
